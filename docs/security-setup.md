# คู่มือติดตั้งระบบยืนยันตัวตนใหม่

เอกสารนี้อธิบายขั้นตอนเปลี่ยนจากระบบเดิม (บัญชีนิรนาม + รหัสผ่านในโค้ด)
มาเป็นบัญชี Firebase Auth จริง พร้อมกฎความปลอดภัยของ Firestore

> ทำตามลำดับด้านล่างให้ครบทุกข้อ **ก่อน** deploy
> ถ้า deploy กฎก่อนสร้างบัญชี ทุกคนจะเข้าระบบไม่ได้จนกว่าจะสร้างบัญชีเสร็จ

---

## ระบบเดิมมีปัญหาอะไร

| ปัญหา | ผลที่เกิดขึ้น |
|---|---|
| รหัสผ่านผู้ดูแลระบบเขียนไว้ในไฟล์ `index.html` | ใครกด View Source ก็เป็นแอดมินได้ |
| รหัสผ่านครูเก็บเป็นข้อความธรรมดาใน Firestore | ดาวน์โหลดไปทั้งชุดได้ พร้อมข้อมูลนักเรียน |
| เข้าระบบด้วย `signInAnonymously` | ทุกคนที่เปิดเว็บมี token ที่อ่านฐานข้อมูลได้ |
| `pp1.html` และ `schedule.html` ไม่มีการตรวจสิทธิ์ | เปิด URL ตรงก็เห็นข้อมูลนักเรียนทันที |

---

## ขั้นตอนติดตั้ง

### 1. เปิดใช้การเข้าสู่ระบบด้วยอีเมล

คอนโซล Firebase → **Authentication** → **Sign-in method**
→ เปิด **Email/Password**

ครูไม่ต้องมีอีเมลจริง ระบบสร้างอีเมลสมมติจากรหัสประจำตัวครูให้เอง
เช่น ครูรหัส `id_sdc03vdqx` จะได้บัญชี `id_sdc03vdqx@anpscore.local`

### 2. เตรียมกุญแจสำหรับเครื่องมือผู้ดูแลระบบ

คอนโซล Firebase → **Project settings** → **Service accounts**
→ **Generate new private key** จะได้ไฟล์ `.json`

เก็บไฟล์นี้ไว้ **นอก** โฟลเดอร์โปรเจกต์ และห้าม commit เข้า git

```bash
cd tools && npm install
```

ชี้ตัวแปรแวดล้อมไปที่ไฟล์กุญแจ (PowerShell):

```bash
$env:GOOGLE_APPLICATION_CREDENTIALS = "C:\path\to\serviceAccountKey.json"
```

### 3. สร้างบัญชีผู้ดูแลระบบ

```bash
node tools/anpscore-admin.mjs create-admin ตั้งรหัสผ่านใหม่ที่นี่
```

ใช้รหัสผ่านใหม่ **อย่าใช้ `0918586632` เดิม** เพราะรหัสนั้นเปิดเผยอยู่ในโค้ดที่ deploy ไปแล้ว
ต้องถือว่าหลุดไปเรียบร้อยแล้ว

### 4. สร้างบัญชีให้ครูทั้งหมด

```bash
node tools/anpscore-admin.mjs provision-teachers
```

คำสั่งนี้จะ

- สร้างบัญชี Firebase ให้ครูทุกคนที่ยังไม่มี โดย**ใช้รหัสผ่านเดิมของแต่ละคน** ครูจึงเข้าระบบได้เหมือนเดิม
- ครูที่รหัสเดิมสั้นกว่า 6 ตัวอักษร (Firebase ไม่รับ) จะได้รหัสใหม่ที่ระบบสุ่มให้ และ**พิมพ์ออกมาบนหน้าจอครั้งเดียว** ให้จดไว้แจ้งเจ้าตัว
- ลบรหัสผ่านเดิมออกจากฐานข้อมูลเมื่อสร้างบัญชีสำเร็จ
- อัปเดตรายชื่อสำหรับหน้าเข้าสู่ระบบให้อัตโนมัติ

รันซ้ำได้ ครูที่สำเร็จแล้วจะถูกข้าม

ตรวจผลด้วย:

```bash
node tools/anpscore-admin.mjs list
```

### 5. deploy กฎความปลอดภัยและหน้าเว็บพร้อมกัน

```bash
firebase deploy --only firestore:rules,hosting
```

> **เรื่อง index**: ไฟล์ `firestore.indexes.json` มีเฉพาะ index ที่โค้ดต้องใช้
> ถ้าโปรเจกต์เคยสร้าง index อื่นไว้จากคอนโซล ให้ดึงของจริงมาก่อนด้วย
> `firebase firestore:indexes > firestore.indexes.json`
> แล้วค่อย deploy ด้วย `--only firestore:indexes` เพื่อไม่ให้ index เดิมหาย

### 6. ตรวจสอบ

- เปิดเว็บในหน้าต่างไม่ระบุตัวตน ต้องเห็นหน้าเข้าสู่ระบบ และ **ไม่มี**การเรียก Firestore ก่อนล็อกอิน
- เปิด `pp1.html` ตรง ๆ ต้องถูกพากลับมาหน้าเข้าสู่ระบบ
- เปิด `schedule.html` ตรง ๆ ต้องถูกพากลับมาเช่นกัน
- ล็อกอินเป็นครูหนึ่งคน แล้วลองเปลี่ยนรหัสผ่านที่หน้าตั้งค่าโปรไฟล์

## งานประจำหลังติดตั้ง

| ต้องการ | วิธีทำ |
|---|---|
| เพิ่มครูใหม่ | หน้าเว็บ → จัดการรายวิชา/บุคลากร → เพิ่มบุคลากรใหม่ (ระบบสร้างบัญชีให้อัตโนมัติ) |
| ครูลืมรหัสผ่าน | `node tools/anpscore-admin.mjs reset-password <teacherId> <รหัสใหม่>` |
| ครูย้ายออก | หน้าเว็บ → ลบครู (ระบบจะปิดสิทธิ์บัญชีให้) หรือ `disable <teacherId>` |
| ครูเปลี่ยนรหัสเอง | หน้าตั้งค่าโปรไฟล์ ต้องกรอกรหัสผ่านปัจจุบันก่อน |
| ชื่อครูในหน้าล็อกอินไม่ตรง | ล็อกอินเป็นแอดมินแล้วกด "อัปเดตรายชื่อหน้าเข้าสู่ระบบ" หรือ `sync-directory` |

> ผู้ดูแลระบบ **ตั้งรหัสผ่านให้ครูจากหน้าเว็บไม่ได้แล้ว** เพราะ Firebase ไม่อนุญาตให้ทำจากเบราว์เซอร์
> ต้องใช้คำสั่ง `reset-password` ซึ่งเป็นข้อจำกัดที่ตั้งใจ ไม่ใช่ข้อบกพร่อง

## เรื่องที่ยังต้องจัดการต่อ

1. **รหัสผ่านเดิมถือว่าหลุดแล้วทั้งหมด**
   โค้ดที่ deploy ไปก่อนหน้านี้เปิดให้ใครก็ได้อ่านรหัสผ่านครูทุกคน
   ควรให้ครูทุกคนเปลี่ยนรหัสผ่านหลังติดตั้งเสร็จ

2. **ข้อมูลค้างในเบราว์เซอร์ของเครื่องที่เคยใช้งาน**
   ระบบเดิมเก็บสำเนาฐานข้อมูล (รวมรหัสผ่าน) ไว้ใน localStorage
   เครื่องที่ใช้ร่วมกันควรล้างข้อมูลเว็บไซต์นี้ทิ้งหนึ่งครั้ง

3. **โปรเจกต์ `school-survey-2569` ยังไม่ได้ตรวจ**
   `pp1.html` อ่านข้อมูลจากโปรเจกต์ Firebase อีกตัวหนึ่ง ซึ่งเก็บ
   เลขบัตรประชาชน วันเกิด และข้อมูลบิดามารดาของนักเรียน
   โค้ดฝั่งนี้เรียกอ่านโดย**ไม่ล็อกอินเลย** แปลว่ากฎของโปรเจกต์นั้นน่าจะเปิดให้อ่านสาธารณะ
   กฎในโปรเจกต์นี้คุมไปไม่ถึง ต้องเข้าไปแก้ที่โปรเจกต์นั้นแยกต่างหาก

4. **ใช้งานออฟไลน์ครั้งแรกไม่ได้**
   การล็อกอินต้องต่ออินเทอร์เน็ต หลังล็อกอินแล้วถ้าเน็ตหลุด ระบบยังทำงานต่อจากข้อมูลในเครื่องได้

## บันทึกการตรวจโมดูลตารางสอน

ตรวจ `schedule.html` และ `schedule/*.js` (ประมาณ 6,000 บรรทัด) พบและแก้แล้ว

| เรื่อง | สภาพเดิม | สถานะ |
|---|---|---|
| `schedule.html` ไม่เคยโหลด `schedule/cloud.js` | อีเวนต์ `tt-cloud-ready` ไม่เคยยิง หน้าค้างที่หน้าเริ่มระบบตลอด ใช้งานไม่ได้เลย | แก้แล้ว |
| รหัสผ่านผู้ดูแลระบบฝังในโค้ด | `schedule/app.js` มีค่าเดียวกับระบบคะแนน | ลบแล้ว |
| เทียบรหัสผ่านครูในเบราว์เซอร์ | อ่าน `t.password` จากฐานข้อมูลมาเทียบตรง ๆ | ใช้ Firebase Auth แทน |
| หน้าเข้าสู่ระบบซ้ำซ้อน | มีหน้าล็อกอินของตัวเองแยกจากระบบคะแนน | ลบออก ใช้บัญชีร่วมกัน |

ส่วนที่ตรวจแล้วไม่พบปัญหา

- การตรวจคาบชนกัน (`E.checkEntry`) ครอบคลุมทั้งห้องเรียนซ้ำ ครูซ้ำ ห้องพิเศษซ้ำ และครูร่วมสอน
- `TT.entriesOfTeacher` นับครูร่วมสอนด้วย การหาครูว่างมาสอนแทนจึงไม่พลาด
- ไม่พบการเรียกฟังก์ชันที่ไม่มีอยู่จริงเลยทั้งโมดูล

### ข้อจำกัดที่ควรทราบ

ระบบสิทธิ์ภายในตารางสอน (`TT.can`) ตรวจที่ฝั่งเบราว์เซอร์อย่างเดียว
ครูที่ล็อกอินแล้วสามารถแก้ค่าในเครื่องมือนักพัฒนาเพื่อให้เมนูจัดตารางสอนโผล่ขึ้นมาได้
กฎของ Firestore อนุญาตให้บุคลากรทุกคนเขียนข้อมูลตารางสอนได้อยู่แล้ว
สิทธิ์ชุดนี้จึงเป็นการแบ่งหน้าที่การทำงาน ไม่ใช่การกันคนนอก
ถ้าต้องการบังคับจริงจัง ต้องย้ายการตรวจสิทธิ์ไปไว้ใน `firestore.rules`
